# RPS Init Cards (v2.0)

Программный комплекс для поточной инициализации бесконтактных смарт-карт (Mifare Classic 1K / 4K), записи ключей объекта и автоматической загрузки базы карт в Microsoft SQL Server (БД `rpsMDBG`) парковочной системы RPS через защищенный SSH-туннель.

Поддерживается как классический **ручной режим** (поднесение карт оператором к USB PC/SC или RS-232 считывателю), так и полностью **автоматический режим** (высокоскоростная выдача из моторизованного диспенсера карт с сортировкой брака).

---

## 🚀 Основные возможности

### 1. Режимы работы с оборудованием
* **Автоматический режим (Диспенсер MT166 + считыватель MT625):**
  * Подача карты из стопки под антенну считывателя.
  * Чтение UID и валидация текущего состояния чипа.
  * Запись уникального ключа объекта в заданный сектор и верификация записи (EEPROM delay + повторная аутентификация).
  * **Автосортировка:** при успешной прошивке карта выдается оператору наружу (`eject`), а при обнаружении дефекта (нечитаемый чип, чужой/неизвестный ключ, ошибка записи) — автоматически сбрасывается во встроенную корзину брака (`retain`).
* **Ручной режим (Manual):**
  * **Omnikey** — работа с любыми стандартными PC/SC считывателями (Omnikey 5022, 5422, 5321 и др.) по USB.
  * **MT625** — работа со считывателем MT625 по прямому последовательному интерфейсу (RS-232 / USB-UART COM-порт).

### 2. Интеграция с базой данных MS SQL (`rpsMDBG`)
* **Пакетная запись (Batching):** карты накапливаются в памяти и отправляются в базу данных пачками (по умолчанию по 10 карт), что исключает сетевые задержки механики диспенсера.
* **Гарантированное сохранение:** при завершении работы (ввод `q`, Ctrl+C) или при опустошении магазина диспенсера весь накопленный остаток карт немедленно сохраняется в БД.
* **Автоматический бэкап:** перед первой записью партии карт система автоматически инициирует создание резервной копии базы данных на сервере (`rpsMDBG_backup_YYYYMMDD_HHMMSS.bak`).
* **SSH-туннелирование:** безопасное подключение к серверу через `plink.exe` (PuTTY) с поддержкой аутентификации по паролю и проверкой отпечатка хоста.

### 3. Логирование и учет
* Каждая успешно выданная карта мгновенно записывается в локальный журнал `issued_YYYY-MM-DD.csv` (UID, десятичный номер, метка времени).
* Поддерживается импорт готовых списков карт из текстового файла или CSV методом drag-and-drop на окно программы.

## 🛠 Аппаратные требования и настройка

### 1. Диспенсер карт MT166 (Card Dispenser & Collector)
* **Интерфейс:** RS-232 (COM-порт).
* **Параметры порта:** `9600` бод, `8` бит данных, четность `None`, `1` стоп-бит (`9600 8N1`).
* **Конфигурация DIP-переключателей (блок из 8 DIP):**
  * **DIP 1:** `ON` (Вверх)
  * **DIP 2:** `ON` (Вверх)
  * **DIP 3..8:** `OFF` (Вниз)
  *(Соответствует скорости 9600 бод и базовому адресу устройства `0x00`)*.
* Подробная спецификация протокола доступна в файле [MT166_DISPENSER_PROTOCOL.md](MT166_DISPENSER_PROTOCOL.md).

### 2. Считыватель карт MT625
* **Интерфейс:** RS-232 / USB-UART (COM-порт).
* **Параметры порта:** `115200` бод, `8` бит данных, четность `None`, `1` стоп-бит (`115200 8N1`).
* Подробная спецификация бинарного протокола считывателя доступна в файле [MT625_PROTOCOL.md](MT625_PROTOCOL.md).

### 3. Считыватель Omnikey
* Подключение по USB. Необходим установленный в ОС драйвер смарт-карт (служба Windows Smart Card / PC/SC).

## ⚙ Конфигурация (`settings.txt`)

Параметры программы настраиваются в файле `settings.txt` в каталоге с исполняемым файлом. При первом запуске файл создается автоматически со значениями по умолчанию. Пример файла:

```ini
# Параметры подключения к серверу RPS
host=127.0.0.1
port=2325
user=Server

# Ключ чистых карт Mifare по умолчанию
factory_key=ffffffffffff

# Режим работы:
# 1 - Ручной режим
# 2 - Автоматический режим (Диспенсер MT166 + MT625)
mode=2

# Тип считывателя для ручного режима:
# 1 - Omnikey (USB PC/SC)
# 2 - MT625 (RS-232)
reader_type=1

# Номера COM-портов (можно задавать "10" или "COM10")
dispenser_port=COM10
mt625_port=COM12

# Размер пачки карт для пакетной отправки в MS SQL
batch_size=10
```

## 📂 Структура проекта

* `rps_cards.py` — Главный модуль приложения: логика взаимодействия с оператором, SSH/SQL команды, координация прошивки и сохранения.
* `dispenser.py` — Драйвер моторизованного диспенсера карт MT166 (подача, выброс, сброс в отказник, мониторинг датчиков).
* `mt625.py` — Драйвер бесконтактного считывателя MT625 (чтение UID, аутентификация по Key A/B, запись трейлера сектора с верификацией).
* `MT166_DISPENSER_PROTOCOL.md` — Документация протокола диспенсера MT166.
* `MT625_PROTOCOL.md` — Документация протокола считывателя MT625.
* `settings.txt.example` — Шаблон файла настроек.
* `requirements.txt` — Список зависимостей Python.
* `rps_cards.spec` — Конфигурация сборщика PyInstaller.

## 📦 Установка и запуск из исходного кода

### Требования
* Python 3.10 или новее.
* Windows 10 / 11 / Server.

### Установка зависимостей
```bash
pip install -r requirements.txt
```

### Запуск
```bash
python rps_cards.py
```

---

## 🔨 Сборка исполняемого файла (.EXE)

Для создания автономного исполняемого файла `rps_cards.exe`, включающего в себя все зависимости и утилиту `plink.exe`:

```bash
pyinstaller --clean rps_cards.spec
```

Готовый файл и сопутствующие файлы будут размещены в каталоге `dist/rps_cards.exe`.

## 📝 Журнал изменений (Changelog v2.0)

* **Добавлен драйвер считывателя MT625 (`mt625.py`):**
  * Реализован низкоуровневый RS-232 протокол (115200 8N1).
  * Корректная авторизация в секторах Mifare Classic 1K по заводскому ключу и ключу объекта.
  * Формирование трейлера блока (Key A + Access Bits + Key B).
  * Введена задержка EEPROM (80 мс) и обязательная пост-верификация успешности записи перед выдачей карты.
* **Добавлен драйвер диспенсера карт MT166 (`dispenser.py`):**
  * Подача карты точно под внутреннюю антенну считывателя (`SendFromBoxToReadPosition`).
  * Выдача валидной карты наружу (`SendCardToBezelAndNotHold`).
  * Сброс карты с дефектом или чужим ключом в корзину брака (`SendCardToRecycleBox`).
  * Побайтовый парсинг статусов датчиков (наличие карты под антенной, карта в губах, опустошение стопки, замятие).
* **Автоматизация поточной выдачи:**
  * Полноценный непрерывный цикл работы: автоматическая подача -> кодирование -> контроль -> выдача/брак.
  * Пакетная фиксация в БД (`batch_size`) для исключения простоев оборудования на сетевых запросах.
  * Автоматический сброс остатка очереди при выходе или пустом магазине.
* **Конфигурация:**
  * Сохранение и автоматическое восстановление портов и режимов через `settings.txt`.
  * Нормализация ввода номеров портов (`COM10` / `10`).
